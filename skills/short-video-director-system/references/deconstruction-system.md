# 拆片与对标分析

本参考用于账号拆片、单条视频拆解、对标账号比较、跨视频规律归纳和复用决策。目标不是复制爆款，而是把公开样本转换为可验证的内容假设。

这些路径只是读取指针；不要假设模型、工具或 Obsidian 链接会自动加载文件。动态 MOC 与卡片为当前 canonical 口径，模板用于直接交付。连接失败时，本文件作为离线基线独立使用。

## 什么时候使用

- 用户要分析一个账号为什么有效；
- 用户提供若干视频，希望拆出选题、脚本、呈现和剪辑；
- 用户要找对标账号、建立拆片表或总结可复用模式；
- 用户想比较高表现与普通表现内容；
- 用户要把对标观察转成自己的选题、脚本或小规模测试。

如果用户只要单条视频分析，仍保留账号背景、证据坐标和不确定性，但不强行做跨视频规律。

## 最小输入

优先获得：

- 平台与公开账号或视频链接；
- 用户自己的业务、产品、IP 和目标人群；
- 本次目标：流量、人设、成交或具体问题；
- 样本时间窗与可见数据；
- 输出形式：单条拆解、账号画像、对标比较或复用方案。

信息缺失时可以明确假设后继续，但不得编造粉丝、点赞、评论、成交、身份、经历或平台机制。

## 核心方法

标准链路：

数据事实 → 结构观察 → 跨样本规律 → 竞争性假设 → 可控变量 → 小规模验证 → 复用或放弃

始终分开三层：

1. 数据：直接看见或按统一口径计算的事实；
2. 假设：对数据的可能解释，必须允许竞争性解释；
3. 复用：结合自己业务后可控制、可验证、合规的动作。

## 样本选择

课程底稿提出“没有商业属性不拆、营销号不拆”。执行时解释为：

- 优先选择能连接人群需求、业务场景、信任或成交的内容；
- 排除只有口号、搬运或硬广、缺少结构学习价值的样本；
- 不只选择最高数据，要同时保留普通样本与反例；
- 固定平台、观察时间窗、采集时间和纳入/排除条件；
- 样本不足时写“证据不足”，不制造规律。

## 账号层字段

多账号分析时，先为每个账号分配 A01、A02 等稳定编号，每个账号分别填写账号层；单条视频通过“所属账号编号”回连。

| 字段 | 记录要求 |
|---|---|
| 账号编号（执行补充） | 用于多账号映射；不是课程原图字段。 |
| 名称 | 公开名称、主页链接或账号标识。 |
| 粉丝 | 公开可见值与采集时间；历史快照不回写。 |
| 行业 | 主营业务、细分品类、服务场景；不确定时标注推测。 |
| 人设 | 只基于公开简介、长期表达、可见经历和行为证据。 |
| 内容配比 | 固定样本中的类别条数或比例，同时记录样本数。 |
| 发布频率 | 在明确时间窗内统计。 |
| 发布时间 | 日期、时段和时区；不直接推断平台偏好。 |
| 简介/昵称 | 来源原图的合并字段为“简介昵称”；执行时将昵称和简介分开记录。 |

## 单条视频层字段

先记录视频编号、所属账号编号、公开链接、发布时间和数据采集时间，再填写：

| 字段 | 记录要求 |
|---|---|
| 点赞 | 采集时公开可见值；隐藏时写“未公开”。 |
| 评论 | 采集时公开可见值；少数评论不代表全部观众。 |
| 主题/IP | 具体主题，以及由谁、以什么稳定身份或栏目表达。 |
| 爆款元素 | 实际出现的注意力元素及镜头或文案证据。 |
| 剪辑特效 | 字幕、花字、缩放、转场、画中画、音效、音乐及其作用。 |
| 选题和类型 | 一句话选题承诺，以及拆片观察标签。 |
| 写作对象 | 内容替谁表达、反驳谁、劝说谁或帮助谁。 |
| 脚本结构 | 实际信息顺序：开篇、问题、冲突、论据、步骤、转机、结果、结尾。 |
| 拍摄呈现 | 口播、采访、对话、跟拍、情景还原、操作演示、素材混剪等。 |
| 备注 | 异常、缺失、待核、反例、评论信号和其他重要信息。 |

原图还单列“人群”和“我的行业选题”。每条视频完成结构观察后，要独立记录明确人群、写作对象/关系、迁移到自己行业后的选题，以及必须替换的事实和表达。

不同账号之间不要仅凭点赞、评论绝对值判断优劣。粉丝基础、发布时间、投放、平台阶段和样本窗口都可能影响数据。

## 拆片观察标签与四类脚本

拆片观察标签可用：

- 知识：判断、解释、方法、步骤或避坑；
- 过程：任务推进、制作、服务、体验、变化或结果；
- 观点：立场、判断、评价或价值选择；
- 故事：人物、事件、冲突、行动和变化；
- 产品：产品、功能、效果、价格、使用或购买理由；
- 其他：混合、信息不足或尚未形成稳定类型。

四类脚本是知识、观点、故事、晒过程，用于创作路由。拆片标签只描述看到的内容：

- 产品不是第五种脚本；
- 过程不自动等于晒过程；
- 进入创作时必须重新判断人群、目标、证据与中心承诺。

## 标准拆片流程

### 1. 写清问题

明确用户自己的业务、人群、目标和本次要验证的问题。没有问题的拆片只会制造字段库存。

### 2. 锁定样本

记录平台、账号、时间窗、样本量、采集时间与纳入/排除条件。口径变化时另开一轮。

### 3. 填账号层

记录稳定背景。行业、人设等解释性字段要附公开证据或标注推测。

### 4. 填单条视频层

先记录链接、时间和公开数据，再记录主题、元素、结构、呈现和剪辑。事实与解释分开写。

### 5. 统一编码

同轮分析使用一致标签和粒度。先写具体观察，再归一为可统计标签。

### 6. 做跨视频归纳

至少比较：

- 内容配比；
- 人群与写作对象；
- 主题/IP 与稳定栏目；
- 爆款元素；
- 脚本结构；
- 拍摄呈现；
- 剪辑特效；
- 发布频率和时段；
- 高值、常态、低值和异常数据。

每个规律关联具体视频编号，同时查找反例和可能的干扰变量。

### 7. 形成竞争性假设

不能看到高数据就直接写“因为某个技巧”。至少提出主假设与一个竞争性解释。

示例：

- 数据：三条高评论样本都在前 5 秒展示改造前后对比；
- 假设 A：对比降低理解成本并激发讨论；
- 假设 B：案例户型本身争议更强，评论不是由对比镜头单独造成；
- 需要证据：同类户型中有无不使用对比的反例，以及相同结构的普通表现样本。

### 8. 转成可控变量

可以提取：

- 信息顺序；
- 证据展示时机；
- 问题与结果的距离；
- 真实场景和人物关系；
- 脚本字段；
- 拍摄呈现；
- 剪辑强调点。

不要复制原文、人物设定、私密信息、商标表达或不可复制资源。

### 9. 做复用决策

按以下顺序判断：

业务匹配 → 真实证据 → 可控程度 → 制作成本 → 合规风险 → 验证价值

决策选项：

- 直接复用：通用结构或工作方法完全匹配；
- 改造复用：原理可用，人群、场景、IP、产品或表达必须重写；
- 小测验证：有重复信号，但因果仍不清；
- 放弃：依赖虚假承诺、侵权表达、私密信息、平台漏洞或不可复制资源。

## 默认交付格式

1. 分析问题与样本边界；
2. 账号层画像和统计口径；
3. 单条视频拆片表；
4. 跨视频重复模式、证据编号和反例；
5. 数据、主假设和竞争性解释；
6. 可复用变量与禁止复制项；
7. 复用决策和小测方案；
8. 推翻条件与合规说明。

如果用户要求可填写版本，显式读取动态 TPL-拆片表；连接失败时按本参考中的字段生成同结构模板。

## 合规与事实边界

- 只分析合法获得的公开内容，不绕过登录、权限、付费墙、访问限制或安全措施。
- 不收集、披露或推断敏感、私密个人信息。
- 不大段复制对标账号的文案、画面、音乐、商标或人物设定。
- 不伪造数据、客户案例、资历、产品效果或平台内幕。
- 所有公开数据记录采集时间；隐藏数据写“未公开”。
- 相关性不是因果，不把拆片结果写成算法权重、流量公式或爆款保证。
- 涉及当前平台规则、违规或推荐机制时，查询最新官方资料，并区分官方事实、课程模型与分析假设。
- 医疗、金融、法律、功效、价格等高风险表达按行业要求单独核验。

## 自检

- 是否写清了分析问题和样本边界？
- 是否完整记录账号层与单条视频层字段？
- 是否把数据事实、解释假设和复用决策分开？
- 是否保留了普通样本、反例和竞争性解释？
- 是否把拆片标签误当成四类脚本？
- 是否提取可控变量，而非复制表达成品？
- 是否记录采集时间、来源链接和不确定性？
- 是否给出验证方法与推翻条件？
- 是否完成版权、隐私、数据和平台规则检查？
